
-Target activity-
You are an assistant helping a researcher perform a realist-synthesis style analysis of education interventions for clinical reasoning.

-Goal-
Given a text document, extract CMO-relevant claims that can support verification against a human-written review:
- Context (who/where/when/setting)
- Intervention (what was done)
- Mechanism (why/how it works)
- Outcome (what changed and how measured)

-Critical constraints (to avoid noise and improve verification quality)-
0) The input document contains a METADATA block:
   - Between "### METADATA (IGNORE FOR ENTITY/CLAIM EXTRACTION)" and "### END_METADATA"
   - This block is for traceability only.
   - DO NOT extract claims from it.

0.1) Formatting robustness (important for GraphRAG parsing):
   - Output MUST be a single list, with records separated ONLY by {record_delimiter}.
   - Each record MUST be exactly ONE parenthesized tuple with 8 fields (subject, object, type, status, start, end, description, source_text).
   - NEVER output special tokens like "<|DIFF_MARKER|>" or fragments like "(\"ENTITY\"".
   - NEVER include "{tuple_delimiter}" or "{record_delimiter}" inside Subject/Object/Description/Source Text (use them only as delimiters).

1) Claims MUST be grounded in the paper text and should be CMO-useful:
   - **PREFER these patterns** (in order of priority):
     * MECHANISM_EXPLANATION: I→M, C→M (how/why interventions work, what contexts enable mechanisms)
     * CONTEXT_MODERATOR: C→O, C→M (who/where/when conditions affect outcomes/mechanisms)
     * INTERVENTION_EFFECT: I→O (direct effects when mechanism is implicit)
     * OUTCOME_MEASUREMENT: (any entity) → O (how outcomes were measured; use sparingly, only when measurement method is central)
   - **BALANCE**: Aim for roughly 30-40% MECHANISM_EXPLANATION, 20-30% CONTEXT_MODERATOR, 20-30% INTERVENTION_EFFECT, 10-20% OUTCOME_MEASUREMENT.

2) Outcome definition (realist-friendly):
   - Outcome can be measured OR clearly reported/observed (e.g., perceived confidence, satisfaction, engagement),
     as long as it is an endpoint/change supported by evidence in the text.
   - Outcome must NOT be bibliographic metadata.

3) Anti-bibliography blacklist (do not use as claim subject/object unless truly part of the intervention/context):
   - Authors/person names; journal/publisher names; DOI/URL; years/dates as standalone; citation fragments.

4) Traceability via span (not long quotes):
   - In Claim Source Text, include a SHORT snippet (1–2 sentences max) and keep any "[PAGE N]" marker if present.
   - Do not paste long paragraphs.
   - If you cannot provide a concrete evidence snippet for a claim, DO NOT output that claim.

5) Output cleanliness (important for auditability):
   - Subject/Object must be clean entity names only (NO numbering like "1.", NO bullets, NO parentheses wrappers).
   - Do NOT include ":" or ";" inside Subject/Object.
   - Keep Subject/Object short (<= 10 words) but specific.

5.1) Avoid unhelpful subjects/objects:
   - Do NOT use generic placeholders like "THE RESULTS", "THE STUDY", "INTERVENTION", "LEARNING" as subject/object.
   - Prefer concrete C/M/O entities (e.g., LOW KNOWLEDGE, SELF-EFFICACY, COGNITIVE LOAD, DIAGNOSTIC ACCURACY).

-Steps-
1. Extract named entities that match the provided entity specification (names or types).
2. For each entity, extract claims that match the description. Prefer claims that explicitly connect:
   - Context → Mechanism
   - Intervention → Mechanism
   - Intervention → Outcome
   - Context → Outcome (moderation)
   - Comparator → Outcome
3. For each claim, extract:
   - Subject: entity that is the subject of the claim (capitalized)
   - Object: entity affected or related (capitalized). Prefer NOT to use **NONE**.
     - For these claim types, Object MUST NOT be NONE: INTERVENTION_EFFECT, CONTEXT_MODERATOR, MECHANISM_EXPLANATION, OUTCOME_MEASUREMENT.
   - Claim Type: a reusable category (e.g., INTERVENTION_EFFECT, MECHANISM_EXPLANATION, CONTEXT_MODERATOR, OUTCOME_MEASUREMENT)
   - Claim Status: **TRUE**, **FALSE**, or **SUSPECTED**
   - Claim Date: (start_date, end_date) in ISO-8601 or **NONE**
   - Claim Description: short explanation (1–3 sentences) AND include a compact CMO field for verification.
     Use this exact template at the end of the description (single line):
     CMO[C=<context or NONE>; I=<intervention/comparator or NONE>; M=<mechanism or NONE>; O=<outcome or NONE>]
   - Claim Source Text: include the most relevant evidence span/snippet (short, keep any [PAGE N] marker)

Format each claim as:
(<subject_entity>{tuple_delimiter}<object_entity>{tuple_delimiter}<claim_type>{tuple_delimiter}<claim_status>{tuple_delimiter}<claim_start_date>{tuple_delimiter}<claim_end_date>{tuple_delimiter}<claim_description>{tuple_delimiter}<claim_source>)

4. Return output in English as a single list using **{record_delimiter}** as delimiter.
5. When finished, output {completion_delimiter}
